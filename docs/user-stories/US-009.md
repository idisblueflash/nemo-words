# US-009. pick the representative keyword for a new set
As an engineer, I want to ask Claude to pick a representative keyword from the top 60 words, so that the new set has a distinct, easy-to-recognize headword like the existing sets.

## background
Following J.C. Wells' convention, the representative keyword should be the most distinct and easiest to recognize word among the selected 60. This is the same selection logic as an existing set's keyword, just applied to the newly built set.

## Protocol
`nemo-words.keyword/pick-keyword` — `[rows] -> keyword`, taking the top-60 ranked rows from `rank/top-n` and shelling out to the `claude -p` CLI (as a subprocess) to choose the headword (impure: calls out to an external process, so tests mock that call rather than unit-testing the choice itself). Called in-process from [[US-006]]'s `extend-set`, no standalone CLI.

## Acceptance Criteria

```gherkin
Scenario: A distinct headword exists among the top 60
  Given a top-60 word list containing one short, common, unambiguous word
  When pick-keyword is called
  Then it returns that word as the keyword

Scenario: The chosen keyword must be from the given list
  Given any top-60 word list
  When pick-keyword is called
  Then the returned keyword is a member of that list, never an invented word

Scenario: Claude call fails
  Given the `claude -p` subprocess exits non-zero or times out
  When pick-keyword is called
  Then the error propagates clearly (not silently swallowed)
  And extend-set does not write a partial/corrupt entry to lexical-sets.edn
```
