# US-024. Re-seed the Lexical Sets Table against `ga_rp.tsv`

Follow-up to [FEAT-002](FEAT-002.md) (its first "Follow-up" bullet): re-run
`populate-lexical-sets` against the CMUdict/BEEP-backed `ga_rp.tsv` and fix
what's left now that [bug-003](bug-003-mrpa-vowel-mapping-shift.md) (BEEP's
`oh`/`ao`/`ow`/`aw` MRPA table) and
[bug-004](bug-004-lookup-rows-word-case-sensitive.md) (case-sensitive word
lookup) are both fixed.

## Background
Re-running `clojure -M -m nemo-words.core populate-lexical-sets` against
`resources/data/ga_rp.tsv` surfaced two real implementation bugs (now
fixed separately as bug-003 and bug-004) plus what's left over once both
are in: every set matches fully **except**:

- **CURE** drops `poor` (4/5): CMUdict encodes it with the tense vowel
  `UW` (`P UW1 R`, IPA `/uɹ/`), not CURE's lax `/ʊɹ/` target — a genuine
  pronunciation-variant mismatch, not a bug. Verified alternates that do
  match CURE's `ʊə`/`ʊɹ` targets: `sure`, `tour`, `moor`, `endure`, `boor`.
- **happY** drops `scampi` (6/7): BEEP-only word, no CMUdict entry at all,
  so the GA side can never be verified — not a bug. Verified alternates
  matching `i`/`i`: `coffee`, `valley`, `movie`, `alley`, `money`, `curry`,
  `lolly`.
- **commA** drops `catalpa` (2/3): same BEEP-only gap as `scampi` — no
  CMUdict entry. Verified alternates matching `ə`/`ə`: `sofa`, `extra`,
  `camera`, `china`, `banana`, `gala`, `zebra`.
- **lettER** drops all 6 seed words (0/6). This one **is** mostly fixable,
  and isn't a word problem at all: `lexical-sets-table`'s `lettER` row
  uses GA target `"əɹ"` (decomposed vowel + rhotic consonant), but
  CMUdict always encodes word-final -er as the single composed r-colored
  vowel token `ER0` (e.g. `paper` → `P EY1 P ER0`), never as a separate
  vowel+`R` sequence. `"əɹ"` can therefore never match any real GA data,
  regardless of which seed words are chosen. [US-020](US-020.md)'s
  `arpabet->ipa`/`ipa->arpabet` already special-case exactly this: `ER0`
  round-trips through the composed IPA symbol `ɚ` (`rhotic-schwa-ipa`,
  `src/nemo_words/ipa.clj` ~line 78/108/160), not through `"ə"` + `"ɹ"`.
  Confirmed directly:
  ```
  (word-matches? dict "paper" "ə" "əɹ")  ;=> false  (current, broken)
  (word-matches? dict "paper" "ə" "ɚ")   ;=> true   (composed target)
  ```
  same for `metre`, `calendar`, `stupor`, `martyr` — 5 of 6 match once the
  target is `"ɚ"`. `succour` remains a drop, but for an unrelated reason:
  CMUdict only has the American spelling `succor` (`S AH1 K ER0`) while
  BEEP only has the British spelling `succour`, so `build-ga-rp-rows`'s
  exact-word-string union never merges them into one row and `succour`'s
  GA cell is permanently empty — not a target-string bug, and out of
  scope for this story's word-list changes (only CURE/happY/commA's
  seed lists are touched by the Protocol). This isn't the "rhotic
  composed vs. decomposed" limitation [US-015](US-015.md) documented as
  accepted for individual *words* within an otherwise-correct row (e.g.
  NURSE's `hurt`) — it's the row's own *target string* being wrong, so
  every word in the row that has GA data fails uniformly until fixed.
  NURSE/NEAR/SQUARE/START/NORTH/FORCE/CURE's `ɹ`-style GA targets are
  left alone here (they already match fully or near-fully today;
  re-litigating whether they too should use a composed target is out of
  scope).

## Protocol
In `nemo-words.build-set/lexical-sets-table` (`src/nemo_words/build_set.clj`):
- Change the `lettER` row's GA target from `"əɹ"` to `"ɚ"` (RP target
  `"ə"` unchanged).
- Replace `poor` in the CURE row with `sure`.
- Replace `scampi` in the happY row with `coffee`.
- Replace `catalpa` in the commA row with `sofa`.

No changes to any matching/conversion code — this story is entirely a
seed-table data fix, verified by re-running `populate-lexical-sets`
against the real dict.
