# US-011. Upsert a set into lexical-sets.edn
As an engineer, I want a function that writes a keyword's word list into `lexical-sets.edn`, so building or extending a set doesn't mean hand-editing the EDN file.

## background
[[US-004]] and [[US-006]] both end with "save this keyword + word list into the lookup table." One writer function handles both: create the entry if missing, replace it if the keyword exists, leave every other entry untouched.

## Protocol
`nemo-words.sets/upsert` — pure: `[lexical-sets keyword rows] -> lexical-sets'`, replacing any existing entry for `keyword` and leaving the rest of the map untouched. Unit-tested directly on in-memory maps.
`nemo-words.sets/save!` — thin, impure wrapper: writes the resulting map to `lexical-sets.edn` (create the file if missing); on write failure, leaves the file untouched. Called once at the end of [[US-004]]'s `build-set` / [[US-006]]'s `extend-set`, no standalone CLI.

## Acceptance Criteria

```gherkin
Scenario: Create a new entry
  Given a lexical-sets map with no entry for "nurse"
  When upsert is called with keyword "nurse" and a word list
  Then the returned map has a "nurse" entry with that word list
  And every other entry is unchanged

Scenario: Update an existing entry
  Given a lexical-sets map with an existing "nurse" entry
  When upsert is called with keyword "nurse" and a new word list
  Then the "nurse" entry is replaced with the new word list
  And every other entry is unchanged

Scenario: Save creates the file if missing
  Given lexical-sets.edn does not exist on disk
  When save! is called with a non-empty map
  Then lexical-sets.edn is created containing that map, readable back via clojure.edn/read-string

Scenario: Save overwrites the file if present
  Given lexical-sets.edn already exists with different content
  When save! is called with an updated map
  Then the file's contents equal the new map exactly

Scenario: Save fails
  Given the target path is not writable
  When save! is called
  Then it throws (propagates the underlying I/O exception uncaught — same "don't swallow errors" convention as [[US-009]]'s Claude-call-fails scenario), so [[US-004]]'s `build-set` / [[US-006]]'s `extend-set` never silently continue past a failed save
  And the pre-existing file (if any) is left untouched
```
