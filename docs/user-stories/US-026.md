# US-026. Cross-ref wikipron-uk/en_UK to backfill missing RP cells

## Background
`resources/data/ga_rp.tsv` (US-019) unions `:cmudict-raw` (GA) and
`:beep-raw` (RP) into one word -> {GA, RP} table. 294,408 rows; 168,485
(57.2%) missing GA, 57,655 (19.6%) missing RP, 0 missing both.

`_david`'s investigation cross-referenced four other dicts already in
`resources/data/` — `en_US.txt`, `en_UK.txt`, `wikipron_us_broad.tsv`,
`wikipron_uk_broad.tsv` — plus `kaikki-en.jsonl` (US-025's `.gitignore`'d
Wiktionary dump). Full counts, samples, and per-source breakdown:
[US-026-investigation.md](US-026-investigation.md). Two decisions made
after that investigation narrow this story's scope substantially below
its original ~6.9%-of-the-gap framing:

- **kaikki-en.jsonl is dropped as a source** (not committed to the repo,
  not reliably available — see ADR-0004) — this removes `kaikki-us`/
  `kaikki-rp` from consideration entirely.
- **Cells only fill on two-source agreement** (ADR-0004) — a single
  covering source is never enough, since sampling found wikipron-uk
  crowd-sourced noise (e.g. `lue`, `wor`, `utz`) that only a second
  source can catch.

Combined, these leave **GA with only one candidate cross-ref source**
(`wikipron-us`) — which can never satisfy the two-source rule alone — so
**GA backfill is out of scope for this story**. `en_US.txt` also recovers
0 GA cells regardless (its vocabulary is a subset of cmudict's), so it
was never a viable second GA source. RP keeps two candidate sources
(`en-uk`, `wikipron-uk`), so **this story is RP-only**: it backfills a
missing RP cell when `en-uk` and `wikipron-uk` both cover a word and
agree. The GA gap, and the ~93% of the overall gap that's cmudict's
US-surname vocabulary vs. BEEP's British-surname/place-name vocabulary
talking past each other, remain unaddressed — not fixable from data in
this repo (see Follow-up).

Decisions:
- **Rename brands** for symmetry: `:ipa-dict`->`:ipa-us`,
  `:ipa-dict-uk`->`:ipa-uk`, `:wikipron`->`:wikipron-us`; add
  `:wikipron-uk` (`data/wikipron_uk_broad.tsv`).
- **Scope**: RP cross-ref = `en-uk` + `wikipron-uk` only. No GA
  cross-ref (only one candidate source, can't meet the two-source rule
  — see Background). No kaikki (ADR-0004).
- **Storage: convert to ARPABET/MRPA** (reuse `ipa->arpabet`/`ipa->mrpa`
  from US-020/US-021), not raw IPA — they already tokenize full strings,
  so wikipron's space-separated phones just get joined first.
- **Schema**: 5 columns — `word, ga, rp, ga-source, rp-source` (kept
  symmetric with GA even though only RP backfills today, so a future
  second GA source doesn't require another schema migration). `ga` is
  always native-only (`ga-source` is `"cmudict"` or `""`) for now.
- **Selection rule** (ADR-0004): for a word missing its native RP cell,
  convert every covering cross-ref source's value; **require both
  covering sources** — a cell with only one covering source stays empty
  (no second source to catch a bad transcription); fill only if they
  agree (one distinct value) and tag `rp-source` with the comma-joined
  contributing source names; if they disagree, leave the cell empty —
  never guess from a single source or a disagreement.
- **Report the residue**: write still-empty words (after backfill) to a
  companion file for manual lookup later, instead of discarding them.

## Protocol
- `ipa.clj` `brand->resource`: apply the renames above; add
  `:wikipron-uk -> "data/wikipron_uk_broad.tsv"` (same format as
  `:wikipron-us`). No kaikki brands (dropped, ADR-0004).
- New `backfill-ga-rp-rows` (parallel to `build-ga-rp-rows`): given
  native GA/RP dicts + `en-uk` + `wikipron-uk`, produce
  `{:word :ga :ga-source :rp :rp-source}` rows:
  - `:ga`/`:ga-source` always come straight from the native GA dict
    (`"cmudict"` or `""`) — no GA cross-ref lookup (out of scope, see
    Background).
  - `:rp`: native value wins outright, no cross-ref lookup. Otherwise,
    if both `en-uk` and `wikipron-uk` cover the word, convert each to
    MRPA and compare as **sets of variants** (not raw strings, so
    comma-joined order never causes a false disagreement); agree -> fill
    + `rp-source` is `"en-uk,wikipron-uk"`; disagree, or only one/neither
    covers it -> `""`/`""`.
- `write-ga-rp-dict!`/`default-ga-rp-path`: write the new 5-column TSV
  from `backfill-ga-rp-rows` (replaces the old 3-column writer), plus a
  companion `resources/data/ga_rp_still_missing.txt` listing every word
  still empty on any side, one per line.
- `load-ga-rp-dict`: parse 5 tab-separated fields, returning
  `{:word :ga-tokens :rp-tokens :ga-source :rp-source}` — additive, does
  not change `:ga-tokens`/`:rp-tokens`'s shape, so `lookup-rows`/
  `word-matches?` (US-022) keep working unchanged.
- Re-run `clojure -M -m nemo-words.core build-ga-rp-dict` to regenerate
  and commit `resources/data/ga_rp.tsv` in the new format.
- No release-jar change: `build.clj`'s `excluded-resources` already
  excludes `wikipron_uk_broad.tsv`; just reword the comment justifying
  its exclusion from "unused" to "dev-only build input, not needed at
  runtime" now that `:wikipron-uk` is a real brand.

## Acceptance Criteria

```gherkin
Scenario: a missing RP cell stays empty when only one cross-ref source covers it
  Given beep-raw has no entry for "mojo", en-uk has no entry for "mojo",
    and wikipron-uk has "mojo" -> "m oʊ dʒ oʊ"
  When backfill-ga-rp-rows runs
  Then the "mojo" row's :rp is "" and :rp-source is "" (a single
    covering source is never enough to fill a cell)

Scenario: a missing RP cell is backfilled when both cross-ref sources agree
  Given beep-raw has no entry for "gulag", en-uk's IPA and wikipron-uk's
    phones both convert (via ipa->mrpa) to the same MRPA token string
  When backfill-ga-rp-rows runs
  Then the "gulag" row's :rp is that shared token string and :rp-source
    is "en-uk,wikipron-uk"

Scenario: a missing RP cell stays empty when the two cross-ref sources disagree
  Given beep-raw has no entry for a word, and en-uk's and wikipron-uk's
    converted MRPA token strings differ for that word
  When backfill-ga-rp-rows runs
  Then that row's :rp is "" and :rp-source is ""

Scenario: a missing GA cell is never backfilled (out of scope this story)
  Given cmudict-raw has no entry for "abaci" and wikipron-us has
    "abaci" -> "ah b ey s ay"
  When backfill-ga-rp-rows runs
  Then the "abaci" row's :ga is "" and :ga-source is "" (GA cross-ref
    is out of scope — only one candidate source exists, which can never
    satisfy the two-source rule)

Scenario: the still-missing word list is reported, not silently dropped
  Given backfill-ga-rp-rows leaves some rows' :ga and/or :rp empty
    after checking every native and cross-ref source
  When write-ga-rp-dict! runs
  Then a companion report lists every word with at least one side still
    empty, one per line

Scenario: a native RP cell is never touched by cross-ref backfill
  Given beep-raw has "cat" -> "k a t"
  When backfill-ga-rp-rows runs, regardless of what en-uk or wikipron-uk
    also have for "cat"
  Then the "cat" row's :rp is "k a t" and :rp-source is "beep"

Scenario: load-ga-rp-dict parses the new 5-column format
  Given resources/data/ga_rp.tsv has a row
    "mojo\tM OW1 JH OW0\t\tcmudict\t" (example native-GA-only row)
  When load-ga-rp-dict is called
  Then the returned row is {:word "mojo" :ga-tokens "M OW1 JH OW0"
    :rp-tokens "" :ga-source "cmudict" :rp-source ""}

Scenario: lookup-rows/word-matches? keep working unchanged after the schema grows
  Given the dict loaded via the updated load-ga-rp-dict
  When lookup-rows is called with the same :ga/:rp/:pair opts as before
  Then matching behaves exactly as it did pre-US-026 (US-022's ACs still
    pass), ignoring the new :ga-source/:rp-source fields entirely
```

## Follow-up (out of scope here, tracked separately)
- Surfacing `:ga-source`/`:rp-source` in the `ipa-lookup` CLI display
  output is a possible follow-on, not required here.
- **Missing-GA backfill entirely unaddressed by this story** (168,485
  cells): the only candidate cross-ref source is `wikipron-us`, and the
  two-source rule (ADR-0004) means a lone source can never fill a cell.
  Closing any of the GA gap would need a genuinely new second GA source
  (not already in this repo) to agree against.
- The ~93% of the gap this story can't close (cmudict's US-surname vs.
  BEEP's British-surname/place-name vocabulary) needs a different data
  source entirely — not scoped here.
