# US-026. Cross-ref wikipron/en_UK dicts to backfill missing GA/RP cells

## Background
`resources/data/ga_rp.tsv` (US-019) unions `:cmudict-raw` (GA) and
`:beep-raw` (RP) into one word -> {GA, RP} table. 294,408 rows; 168,485
(57.2%) missing GA, 57,655 (19.6%) missing RP, 0 missing both.

`_david`'s investigation cross-referenced four other dicts already in
`resources/data/` — `en_US.txt`, `en_UK.txt`, `wikipron_us_broad.tsv`,
`wikipron_uk_broad.tsv` — plus `kaikki-en.jsonl` (US-025's `.gitignore`'d
Wiktionary dump). Result: **~6.9%** of the gap (15,631/226,140 empty
cells) is recoverable, overwhelmingly real headwords. `en_US.txt`
recovers 0 GA cells (its vocabulary is a subset of cmudict's) and is
dropped. The remaining ~93% is cmudict's US-surname vocabulary vs.
BEEP's British-surname/place-name vocabulary genuinely talking past each
other — not fixable from data in this repo. Full counts, samples, and
per-source breakdown: [US-026-investigation.md](US-026-investigation.md).
Note: that ~6.9% figure counted single-source hits (e.g. wikipron-us
alone); the two-source-minimum rule below (see Decisions) means the
actual addressable slice is smaller — only cells where at least two
cross-ref sources cover *and* agree.

Decisions:
- **Rename brands** for symmetry: `:ipa-dict`->`:ipa-us`,
  `:ipa-dict-uk`->`:ipa-uk`, `:wikipron`->`:wikipron-us`; add
  `:wikipron-uk` (`data/wikipron_uk_broad.tsv`).
- **Scope**: GA cross-ref = `wikipron-us` + `kaikki-us`. RP cross-ref =
  `en-uk` + `wikipron-uk` + `kaikki-rp`. `en_US.txt`/`:ipa-us` excluded
  (0 GA cells recovered).
- **Storage: convert to ARPABET/MRPA** (reuse `ipa->arpabet`/`ipa->mrpa`
  from US-020/US-021), not raw IPA — they already tokenize full strings,
  so wikipron's space-separated phones just get joined first.
- **Schema**: 5 columns — `word, ga, rp, ga-source, rp-source` (per-side
  provenance, since GA/RP backfill independently).
- **Selection rule**: for a word missing its native cell, convert every
  covering cross-ref source's value; **require at least two covering
  sources** — a cell with only one covering source stays empty (no
  second source to catch a bad transcription); with two or more, fill
  only if they all agree (one distinct value) and tag `*-source` with
  the comma-joined contributing source names; if covering sources
  disagree, leave the cell empty — never guess from a single source or
  a disagreement.
- **Report the residue**: write still-empty words (after backfill) to a
  companion file for manual lookup later, instead of discarding them.

## Protocol
- `ipa.clj` `brand->resource`: apply the renames above; add
  `:wikipron-uk -> "data/wikipron_uk_broad.tsv"` (same format as
  `:wikipron-us`); add `:kaikki-us`/`:kaikki-rp -> "data/kaikki-en.jsonl"`
  (two brands, one file) — parse each JSON line, skip if `lang_code` !=
  `"en"` or `sounds` absent, then collect `sounds[].ipa` where `tags`
  include `US`/`General-American`/`GenAm` (`:kaikki-us`) or
  `Received-Pronunciation`/`RP`/`UK` (`:kaikki-rp`). `resource-reader`
  already returns `{}` when the file is missing — no special-casing
  needed for kaikki's absence.
- New `backfill-ga-rp-rows` (parallel to `build-ga-rp-rows`): given
  native GA/RP dicts + the cross-ref dicts above, produce
  `{:word :ga :ga-source :rp :rp-source}` rows:
  - Native value wins outright, no cross-ref lookup.
  - Otherwise convert every covering source's value to ARPABET/MRPA,
    compare as **sets of variants** (not raw strings, so comma-joined
    order never causes a false disagreement). Fewer than two covering
    sources -> `""`/`""` (no single-source fills). Two or more covering
    sources: one distinct value fills the cell + tags every contributing
    source name; more than one distinct value -> `""`/`""`.
- `write-ga-rp-dict!`/`default-ga-rp-path`: write the new 5-column TSV
  from `backfill-ga-rp-rows` (replaces the old 3-column writer), plus a
  companion `resources/data/ga_rp_still_missing.txt` listing every word
  still empty on any side, one per line.
- `load-ga-rp-dict`: parse 5 tab-separated fields, returning
  `{:word :ga-tokens :rp-tokens :ga-source :rp-source}` — additive, does
  not change `:ga-tokens`/`:rp-tokens`'s shape, so `lookup-rows`/
  `word-matches?` (US-022) keep working unchanged.
- Re-run `clojure -M -m nemo-words.core build-ga-rp-dict` to regenerate
  and commit `resources/data/ga_rp.tsv` in the new format. Works
  (smaller) without `kaikki-en.jsonl` locally — that source is additive.
- No release-jar change: `build.clj`'s `excluded-resources` already
  excludes `kaikki-en.jsonl`/`wikipron_uk_broad.tsv`; just reword the
  comment justifying `wikipron_uk_broad.tsv`'s exclusion from "unused"
  to "dev-only build input, not needed at runtime" now that
  `:wikipron-uk` is a real brand.

## Acceptance Criteria

```gherkin
Scenario: a missing GA cell is backfilled when wikipron-us and kaikki-us agree
  Given cmudict-raw has no entry for "abaci", wikipron-us has
    "abaci" -> "ah b ey s ay", and kaikki-us's US-tagged ipa for "abaci"
    converts (via ipa->arpabet) to that same ARPABET token string
  When backfill-ga-rp-rows runs
  Then the "abaci" row's :ga is that shared token string and :ga-source
    is "wikipron-us,kaikki-us"

Scenario: a missing GA cell stays empty when only one cross-ref source covers it
  Given cmudict-raw has no entry for "abaci", wikipron-us has
    "abaci" -> "ah b ey s ay", and kaikki-us has no US-tagged sounds
    entry for "abaci"
  When backfill-ga-rp-rows runs
  Then the "abaci" row's :ga is "" and :ga-source is "" (a single
    covering source is never enough to fill a cell)

Scenario: a missing RP cell stays empty when only one cross-ref source covers it
  Given beep-raw has no entry for "mojo", en-uk has no entry for "mojo",
    kaikki-rp has no RP-tagged sounds entry for "mojo", and wikipron-uk
    has "mojo" -> "m oʊ dʒ oʊ"
  When backfill-ga-rp-rows runs
  Then the "mojo" row's :rp is "" and :rp-source is "" (a single
    covering source is never enough to fill a cell)

Scenario: a missing RP cell is backfilled when two cross-ref sources agree
  Given beep-raw has no entry for "gulag", en-uk's IPA and wikipron-uk's
    phones both convert (via ipa->mrpa) to the same MRPA token string
  When backfill-ga-rp-rows runs
  Then the "gulag" row's :rp is that shared token string and :rp-source
    is "en-uk,wikipron-uk"

Scenario: a missing RP cell stays empty when the covering cross-ref sources disagree
  Given beep-raw has no entry for a word, and en-uk's and wikipron-uk's
    converted MRPA token strings differ for that word
  When backfill-ga-rp-rows runs
  Then that row's :rp is "" and :rp-source is ""

Scenario: kaikki-en.jsonl absent at build time degrades gracefully
  Given resources/data/kaikki-en.jsonl is not present on the classpath
  When load-dictionary-by-brand is called with :kaikki-us or :kaikki-rp
  Then it returns {} (same as any other brand whose resource file is
    missing), and backfill-ga-rp-rows still produces a valid result
    using only the remaining available sources

Scenario: the still-missing word list is reported, not silently dropped
  Given backfill-ga-rp-rows leaves some rows' :ga and/or :rp empty
    after checking every native and cross-ref source
  When write-ga-rp-dict! runs
  Then a companion report lists every word with at least one side still
    empty, one per line

Scenario: a native cell is never touched by cross-ref backfill
  Given cmudict-raw has "cat" -> "K AE1 T"
  When backfill-ga-rp-rows runs, regardless of what wikipron-us also has
    for "cat"
  Then the "cat" row's :ga is "K AE1 T" and :ga-source is "cmudict"

Scenario: load-ga-rp-dict parses the new 5-column format
  Given resources/data/ga_rp.tsv has a row
    "mojo\tM OW1 JH OW0\t\tcmudict\t" (example native-GA-only row)
  When load-ga-rp-dict is called
  Then the returned row is {:word "mojo" :ga-tokens "M OW1 JH OW0"
    :rp-tokens "" :ga-source "cmudict" :rp-source ""}

Scenario: lookup-rows/word-matches? keep working unchanged after the schema grows
  Given the dict loaded via the updated load-ga-rp-dict
  When lookup-rows is called with the same :ga/:rp/:pair opts as before
  Then matching behaves exactly as it did pre-US-026 (US-022's ACs still
    pass), ignoring the new :ga-source/:rp-source fields entirely
```
