# US-007. Find the dominant RP+GA pairing for a missing GA combination
As an engineer, I want a function that ranks RP+GA pairings for a given GA IPA, so that I know which RP+GA pair defines the new set.

## background
Search for the target GA combination, e.g. `/ɑɹ/`, across the word, RP IPA, GA IPA triples and collect every match, e.g. `/ˈnɑː.li/` (RP), `/ˈnɑɹ.li/` (GA). From each match, [[US-013]]'s `extract-nucleus` reduces the row to a `[rp-nucleus ga-nucleus]` fragment — not the whole word's RP transcription — because whole-word RP strings almost never collide across different words, which would make "dominance" trivially 100%-per-word and the proportion meaningless. This story computes the proportion of each distinct fragment pairing across all matches; only the highest-percentage pairing is kept as the new set's defining pair.

## Protocol
`nemo-words.pairs/dominant-pair` — a pure function `[triples target-ga] -> [rp-nucleus ga-nucleus]`, taking the seq of `{:word :rp :ga}` rows from `ipa/lookup-rows` (filtered to `target-ga`) plus the `target-ga` string itself. For each row, calls [[US-013]]'s `pairs/extract-nucleus` (`:rp` `:ga` `target-ga`); rows where it returns `nil` contribute nothing. Tallies the remaining `[rp-nucleus ga-nucleus]` fragments and returns the single highest-percentage pairing. Unit-tested directly on fixture triples — no CLI, no subprocess; called in-process from [[US-006]]'s `extend-set`.

## Acceptance Criteria

```gherkin
Scenario: One RP nucleus clearly dominates
  Given triples where extraction yields RP nucleus "ɑː" paired with GA nucleus "ɑɹ" in 8 of 10 matches (e.g. rows for "car", "far", "star", "gnarly" all reducing to ["ɑː" "ɑɹ"])
  And a different RP nucleus pairs with "ɑɹ" in the other 2 (e.g. two rows reducing to ["ɛə" "ɑɹ"])
  When dominant-pair is called with target-ga "/ɑɹ/"
  Then it returns ["ɑː" "ɑɹ"]

Scenario: Exact tie between two nucleus pairings
  Given triples split evenly 5/5 between two distinct [rp-nucleus ga-nucleus] pairings (e.g. 5 rows reducing to ["ɑː" "ɑɹ"] and 5 rows reducing to ["ɔː" "ɑɹ"])
  When dominant-pair is called
  Then it returns whichever pairing's contributing row occurs first in the input triples (stable on input order, not on pairing content — so re-ordering the input can change the result, but a fixed input always gives the same output)

Scenario: Only one nucleus pairing exists
  Given every contributing row extracts to the same [rp-nucleus ga-nucleus] pair (e.g. "gnarly", "narwhal", and "car" all reduce to ["ɑː" "ɑɹ"], and no other row is present)
  When dominant-pair is called
  Then it returns that single pairing with 100% dominance

Scenario: Row skipped for mismatched syllable count
  Given a triple whose :ga variant has 2 syllables but every :rp variant has a different syllable count (e.g. {:word "narwhal" :rp "/ˈnɑːw.əl/" :ga "/ˈnɑɹ.li/"} — the GA variant "nɑɹ.li" has 2 syllables but the only RP variant "nɑːw.əl" has 3, so [[US-013]]'s extract-nucleus returns nil for it)
  When dominant-pair is called
  Then that row contributes no pairing to the tally
  And the result is computed only from the remaining rows

Scenario: No triples for the target GA
  Given an empty seq of triples (e.g. target-ga "/ʊə/", a combination with zero matching rows in the dictionary)
  When dominant-pair is called
  Then it returns nil rather than a bogus pair or throwing (it's a pure query function — [[US-006]]'s `extend-set` is the one that decides an empty result is reportable, see its "No matches for the given GA at all" scenario)

Scenario: All rows skipped leaves nothing to tally
  Given every row in triples is skipped per the "mismatched syllable count" rule (e.g. every row's GA variant has a different syllable count than any of its RP variants)
  When dominant-pair is called
  Then it returns nil, same as the empty-triples case
```
