# US-017. Add a `:cmudict-raw` brand for raw ARPABET token parsing

Part of [FEAT-002](FEAT-002.md) (split for parallel implementation — see that
feature for the full background). Independent of [US-018](US-018.md) — can be
implemented and tested in parallel.

As an engineer, I want a `:cmudict-raw` brand in `nemo-words.ipa` that
parses CMUdict lines into raw, space-joined ARPABET token strings (stress
digits intact) instead of translated IPA, so [US-019](US-019.md)'s build step has
raw GA tokens to write to `resources/data/ga_rp.tsv`, per
[0003-match-nucleus-against-arpabet-mrpa-tokens](../decisions/0003-match-nucleus-against-arpabet-mrpa-tokens.md).

## background
The existing `:cmudict` brand (`parse-line`, `load-dictionary-by-brand`)
already parses `resources/data/cmudict.dict` — but it runs each line's
ARPABET tokens through the private `arpabet->ipa` function, producing IPA
for the four-source cross-reference lookup tool (`search-word`/`-main`).
That brand and its live-lookup callers are **untouched** by this story.

This story adds a second, parallel brand that reads the same file but
skips the IPA translation step entirely, keeping the raw ARPABET tokens
as-is. It's independent of [US-018](US-018.md)'s BEEP work (different source
file, no shared state beyond both landing in `nemo-words.ipa`) — the two
can be implemented and tested in parallel.

**Merge-conflict note**: because [US-018](US-018.md) lands around the same time
and touches the same file, keep the headword-validity filter (see
Protocol) implemented *inline* within this story's `parse-line` method
rather than as a new shared top-level `def`/`defn` — that avoids both
stories independently defining a same-named symbol and conflicting on
merge.

## Protocol
- `parse-line :cmudict-raw` — same CMUdict line format as the existing
  `:cmudict` method (comment stripped via `hash-splitter`, variant-marker
  suffix like `read(2)` stripped via `paren-splitter`, word lower-cased
  via `clean-word`), but returns the ARPABET tokens joined with a single
  space (e.g. `"K AA1 R"`) instead of calling `arpabet->ipa` on them.
- `brand->resource` gains `:cmudict-raw "data/cmudict.dict"` — same
  physical file as the existing `:cmudict` brand, parsed a second way.
- Headword filter (inline in this method, per the merge-conflict note
  above): skip entries whose word doesn't match `#"^[a-z][a-z'-]*$"`
  after lower-casing.
- `load-dictionary-by-brand :cmudict-raw` works unchanged (it's brand-
  agnostic already) and returns `word -> [raw-token-string, ...]`.

## Acceptance Criteria

```gherkin
Scenario: a simple CMUdict line parses to raw tokens, not IPA
  Given the CMUdict line "CAR K AA1 R"
  When parse-line :cmudict-raw processes it
  Then the result is ["car" ("K AA1 R")]

Scenario: stress digits are preserved
  Given the CMUdict line "CAT K AE1 T"
  When parse-line :cmudict-raw processes it
  Then the result's token string is "K AE1 T", digit intact, not translated to IPA

Scenario: a trailing comment is stripped
  Given the CMUdict line "CAR K AA1 R # some comment"
  When parse-line :cmudict-raw processes it
  Then the result is ["car" ("K AA1 R")]

Scenario: a variant-marker suffix folds into the base word
  Given the CMUdict line "READ(2) R EH1 D"
  When parse-line :cmudict-raw processes it
  Then the result is ["read" ("R EH1 D")]

Scenario: load-dictionary-by-brand :cmudict-raw returns raw tokens for every word
  Given resources/data/cmudict.dict is loaded via load-dictionary-by-brand :cmudict-raw
  When the result is inspected
  Then every value is a vector of raw space-joined ARPABET token strings,
    none of which contain any IPA characters (e.g. no "ɑ", "ʃ", "ˈ")

Scenario: the existing :cmudict brand (IPA) is unaffected
  Given both :cmudict and :cmudict-raw are loaded from the same file
  When "car" is looked up in each
  Then :cmudict returns IPA (e.g. "kˈɑɹ") and :cmudict-raw returns the raw tokens
    ("K AA1 R"), confirming the new brand didn't change the old one's behavior
```
