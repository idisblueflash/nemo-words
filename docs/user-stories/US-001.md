# US-001. Support IPA search for both RP and GA
As an engineer, I want to have a CLI so that I can search word with phonetic symbol.

## background
I export the word, RP IPA, and GA IPA as a en_US_RP_ipa.tsv file (2.5 MB) from the original huge one, then I can build a CLI based on it.

Here's the command we run to download the original dict (.jsonl 3.2GB).
```bash
aria2c -c -x4 -s4 --file-allocation=none \
  -o resources/data/kaikki-en.jsonl \
  https://kaikki.org/dictionary/English/kaikki.org-dictionary-English.jsonl
```

## Data reality (checked against the actual file, 62,894 rows)
`en_US_RP_ipa.tsv` is `word\tRP-cell\tGA-cell`, and the RP/GA cells are **not** clean single transcriptions:
- 14,577 rows (~23%) have an **empty GA cell** (e.g. `a-alike\t/ˈeɪəˈlaɪk/\t`) — no GA transcription exists for that word at all.
- 1,160 rows have **multiple comma-separated RP variants** and 811 rows have multiple GA variants in one cell (e.g. `a\t/eɪ̯/, /ə/, /ˈʌ/\t/eɪ̯/, /ə/, /ʌ/, /ɔ/, /ˈʌ/`), and RP/GA variants are **not positionally paired** — there's no reliable way to know which RP variant goes with which GA variant.

Design decision to resolve this: `lookup-rows` does **not** explode or pair variants. Each output row's `:rp`/`:ga` is the raw cell text exactly as stored — a single string, comma-joined when the source has multiple variants, `""` (not `nil`) when the GA cell is empty. Substring opts (`{:rp ipa}` / `{:ga ipa}`) test containment against that raw string, so a query matching any one variant inside a multi-variant cell still matches the row. Callers needing one disambiguated variant (e.g. [[US-007]]'s `dominant-pair`) must pick it themselves from a row's raw text — `lookup-rows` won't do it for them.

## Protocol
Core logic lives in `nemo-words.ipa/lookup-rows` — a pure function `[dict opts] -> seq of {:word :rp :ga}`, unit-tested directly on in-memory dict fixtures. `opts` is one of `{:word w}` (exact), `{:rp ipa}` / `{:ga ipa}` (substring), or `{:pair [rp ga]}` (exact both — used once [[US-007]]'s in-process caller picks a winner). For `:pair`, "exact" means exact string equality against the row's raw (possibly comma-joined) `:rp`/`:ga` text, per the data-reality note above — not equality against one variant among several.

`core.clj` exposes it as the `ipa-lookup` subcommand (thin: parse args → `lookup-rows` → print TSV `word\tRP\tGA`) because [[US-005]]'s external AI-agent consumer needs a real process boundary.

## Acceptance Criteria

```gherkin
Scenario: Exact word lookup
  Given the dictionary contains the word "car"
  When I look up "car" by word
  Then I get exactly one row: {:word "car" :rp <RP-IPA> :ga <GA-IPA>}

Scenario: Substring match on RP
  Given the dictionary contains words with RP IPA "/ɑː/" as part of their transcription
  When I look up RP substring "/ɑː/"
  Then every returned row's :rp contains "/ɑː/"
  And no row is returned whose :rp does not contain it

Scenario: Substring match on GA
  Given the dictionary contains words with GA IPA "/ɑːr/" as part of their transcription
  When I look up GA substring "/ɑːr/"
  Then every returned row's :ga contains "/ɑːr/"

Scenario: Exact pair match
  Given the dictionary contains words whose RP is "/ˈnɑː.li/" and GA is "/ˈnɑːr.li/"
  When I look up the exact pair ["/ˈnɑː.li/" "/ˈnɑːr.li/"]
  Then every returned row has :rp = "/ˈnɑː.li/" and :ga = "/ˈnɑːr.li/"

Scenario: No matches
  Given the dictionary does not contain the queried word or IPA
  When I perform the lookup
  Then the result is an empty sequence
  And no error is raised

Scenario: Word has no GA transcription
  Given the dictionary contains a word whose GA cell is empty (e.g. "a-alike")
  When I look up that word by :word
  Then the returned row has :ga = "" (not nil)
  And that row is never returned by a :ga substring lookup with a non-empty query

Scenario: Cell has multiple comma-separated variants
  Given the dictionary contains a word whose RP cell is "/eɪ̯/, /ə/, /ˈʌ/"
  When I look up RP substring "/ˈʌ/"
  Then the row for that word is returned
  And its :rp is the full raw cell "/eɪ̯/, /ə/, /ˈʌ/", not just the matched variant

Scenario: CLI wrapper mirrors the function
  Given the `ipa-lookup` subcommand is invoked with the same query
  When lookup-rows would return N rows
  Then stdout contains exactly N TSV lines "word\tRP\tGA"
  And the process exits 0, even for zero matches
```
