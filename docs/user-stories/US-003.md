# US-003. CLI for word frequency with Google's API
As an engineer, I want to get the frequency of a group of words in bulk, as a pure-ish function with a thin CLI wrapper, so that in-process callers (US-004) and ad hoc bulk shell use both work.

## Protocol
Core logic lives in `nemo-words.freq/annotate-freq` — `[rows] -> rows with :freq added`, hitting the Google Ngram endpoint from the [[US-002]] PoC (impure: network I/O, so tests mock the HTTP layer rather than unit-testing the call itself).

`core.clj` exposes it as the `word-freq` subcommand (args or stdin, one word per line → prints TSV `word\tfreq`) for standalone/bulk use; in-process callers ([[US-004]], [[US-006]]) call `annotate-freq` directly on the rows from `ipa/lookup-rows`, no subprocess involved.

## Acceptance Criteria

```gherkin
Scenario: Annotate rows with frequency
  Given a seq of rows [{:word "car" ...} {:word "star" ...}]
  When annotate-freq is called
  Then each row gains a :freq key with a numeric value
  And row order is preserved

Scenario: Unknown word gets zero frequency, not an error
  Given a row for a word absent from the Ngram corpus
  When annotate-freq is called
  Then that row's :freq is 0 (never nil — [[US-010]]'s `(sort-by score-key >)` throws on a nil key, so :freq must always be numeric)
  And no exception is thrown for the batch

Scenario: CLI reads words from args
  Given `word-freq car star` is run
  Then stdout has two TSV lines: "car\t<freq>" and "star\t<freq>"

Scenario: CLI reads words from a file
  Given `word-freq --file words.txt` is run with one word per line
  Then stdout has one TSV line per non-blank line in the file

Scenario: CLI reads words from stdin
  Given words are piped in via stdin, one per line
  When no args or --file are given
  Then the CLI reads from stdin instead
  And produces the same TSV output as the args form
```
