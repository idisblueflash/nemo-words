# US-004. Prepare the custom example words
As an engineer, I want to build an existing lexical set's word list as a single in-process pipeline, so I don't hand-roll lookup+rank+save for every keyword.

## background
With RP and GA as two axes to limit the example words we found, we can select more balanced words fit for existing set. (J. C. Wells selected them with care) We should also order the found words by frequency, about 60 words, then save them into `lexical-sets.edn` as a look up table — as a composition of pure functions, not separate CLI processes:

```clojure
(defn build-set [dict keyword rp ga]
  (->> (ipa/lookup-rows dict {:rp rp :ga ga})
       (freq/annotate-freq)
       (rank/top-n :freq 60)
       (sets/upsert (load-sets) keyword)
       (sets/save!)))
```

- [[US-001]] `ipa/lookup-rows` finds every word matching the set's RP+GA pair.
- [[US-003]] `freq/annotate-freq` scores each by corpus frequency.
- [[US-010]] `rank/top-n` keeps the top 60.
- [[US-011]] `sets/upsert` + `sets/save!` write `<keyword> -> word list` into `lexical-sets.edn`.

This story is `build-set` itself — the four functions it composes are independently buildable and unit-testable in parallel once their data shapes (`dict`, `{:word :rp :ga :freq}` rows, `lexical-sets` map) are frozen; no subprocess or shell pipe involved.

## Acceptance Criteria

```gherkin
Scenario: Build a brand-new set
  Given lexical-sets.edn has no entry for keyword "nurse"
  And the dictionary has more than 60 words matching RP "/ɜː/" and GA "/ɜr/"
  When build-set is called with keyword "nurse", rp "/ɜː/", ga "/ɜr/"
  Then lexical-sets.edn gains an entry for "nurse"
  And that entry has exactly the top 60 words by frequency

Scenario: Rebuild an existing set (idempotent upsert)
  Given lexical-sets.edn already has an entry for keyword "nurse"
  When build-set is called again with the same keyword, rp, ga
  Then the "nurse" entry is replaced (not duplicated)
  And every other entry in lexical-sets.edn is unchanged

Scenario: Fewer than 60 matches exist
  Given the dictionary has only 12 words matching the given RP+GA pair
  When build-set is called
  Then the resulting entry contains all 12 words
  And no error is raised for having fewer than 60
```
