# US-004. Prepare the custom example words
As an engineer, I want to register an existing lexical set's seed words into `lexical-sets.edn`, verified against the current dictionary, so I don't hand-roll lookup+save for every keyword.

## background
`lexical-sets.edn` is a **reference/index table**, not a search result cache: keyword -> `{:rp :ga :words}`, where `:words` comes from [[FEAT-001]]'s Lexical Sets Table (the hand-picked ~5-7 example words per Wells set), not from an open-ended dictionary search. Its primary job is letting the app check "does a set for this pair already exist?" before building/extending one — so [[US-006]]'s `extend-set` doesn't recreate a pair on the fly that's already covered. `:words` itself is **not consumed programmatically by the build pipeline** — neither this story nor [[US-006]] reads it back when building/extending a set. Its only programmatic reader is [[US-005]]'s `pick-example-words-by-ipa`, which returns it as-is to a downstream AI agent; that's a read-only lookup over the finished table, not a mechanism for finding new words, so it doesn't reopen the open-ended-search question this story just closed. Otherwise `:words` is a quick-glance overview for a human skimming the EDN file to grasp what a set/pair contains at a glance. That's also why it stays small and hand-picked rather than growing into a ranked, exhaustive list: an overview doesn't need exhaustiveness.

**No open-ended dictionary search or frequency ranking happens in this story anymore** — there's no more "query by RP/GA, get hundreds of hits, rank by frequency, cap at N." What's left is a small, per-word dictionary lookup used only to verify: `build-set` takes the seed row's `keyword`/`rp`/`ga`/`words`, and for each seed word looks it up in the *current* dict to check it still resolves to that rp/ga pair — the seed table can go stale if the dict is swapped or updated, so a word that no longer matches is dropped rather than silently trusted. Words that pass verification get upserted and saved:

```clojure
(defn build-set [dict keyword rp ga words]
  (->> words
       (filter #(ipa/word-matches? dict % rp ga))
       (sets/upsert (load-sets) keyword {:rp rp :ga ga})
       (sets/save!)))
```

- [[US-001]] provides the lookup primitive `word-matches?` builds on (`lookup-rows dict {:word w}`, then check the row's `:rp`/`:ga` cells contain the target `rp`/`ga`).
- [[US-011]] `sets/upsert` + `sets/save!` write `<keyword> -> {:rp :ga :words}` into `lexical-sets.edn`.

Finding the *best*-matching example for a specific target word (scoring candidates' onset/coda against the target word's own syllable, e.g. target `/ˈnɑɹli/` scoring up a candidate with onset `/n/`, again if its coda matches) is a separate, on-demand, unsaved search — out of scope for this story and belongs to its own future story. That search queries the dict directly; it never reads or writes `lexical-sets.edn`.

Parsing [[FEAT-001]]'s markdown table into `(keyword, rp, ga, words)` tuples to pass into `build-set` is also out of scope here — this story starts from those four values already in hand.
