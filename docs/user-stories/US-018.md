# US-018. Add a `:beep-raw` brand for raw MRPA token parsing

Part of [FEAT-002](FEAT-002.md) (split for parallel implementation — see that
feature for the full background). Independent of [US-017](US-017.md) — can be
implemented and tested in parallel.

As an engineer, I want a `:beep-raw` brand in `nemo-words.ipa` that
parses BEEP lines into raw, space-joined MRPA token strings, so
[US-019](US-019.md)'s build step has raw RP tokens to write to
`resources/data/ga_rp.tsv`, per
[0003-match-nucleus-against-arpabet-mrpa-tokens](../decisions/0003-match-nucleus-against-arpabet-mrpa-tokens.md).

## background
BEEP has no brand yet anywhere in `nemo-words.ipa` — this is new source
integration, not an extension of an existing one (unlike [US-017](US-017.md)'s
CMUdict work). BEEP uses a different phoneme inventory than CMUdict's
ARPABET (MRPA-style, lowercase, non-rhotic): `aa ae ah ao ax ay b ch d dh
ea eh er ia ih iy jh k l m n ng oh ow oy p r s sh sil t th ua uh uw v w y
z zh`. Note the extra RP-specific vowels `ea`/`ia`/`oh`/`ua`/`er` (BEEP's
non-rhotic encoding of what CMUdict spells as vowel+`R`: SQUARE, NEAR,
GOAT, CURE, NURSE) — this story only parses these as opaque raw tokens;
their IPA targets (`ɛə`, `ɪə`, `əʊ`, `ʊə`, `ɜː`) are defined by
[US-021](US-021.md)'s `mrpa-phoneme->ipa` map, not here.

**Known, accepted data-quality gap**: BEEP carries no stress marking at
all (confirmed: zero digit characters anywhere in
`resources/data/beep_uk.dict`'s phoneme fields), unlike CMUdict. This is
a property of the raw data itself, flagged here so it isn't mistaken for
a bug later.

This story is independent of [US-017](US-017.md)'s CMUdict work (different source
file, no shared state beyond both landing in `nemo-words.ipa`) — the two
can be implemented and tested in parallel.

**Merge-conflict note**: because [US-017](US-017.md) lands around the same time
and touches the same file, keep the headword-validity filter (see
Protocol) implemented *inline* within this story's `parse-line` method
rather than as a new shared top-level `def`/`defn`, to avoid both
stories independently defining a same-named symbol and conflicting on
merge.

## Protocol
- `parse-line :beep-raw` — BEEP lines are `WORD<whitespace>phoneme
  phoneme ...` (uppercase headword, lowercase space-separated phonemes,
  no stress digits, `#`-prefixed header/comment lines skipped); word
  lower-cased via `clean-word`, phonemes kept as-is and joined with a
  single space (e.g. `"k aa"`), not translated.
- `brand->resource` gains `:beep-raw "data/beep_uk.dict"`.
- Headword filter (inline in this method, per the merge-conflict note
  above): skip entries whose word doesn't match `#"^[a-z][a-z'-]*$"`
  after lower-casing — excludes BEEP's symbol pseudo-words (e.g.
  `!EXCLAMATION-POINT`, `&AMPERSAND`, `%PERCENT`).

## Acceptance Criteria

```gherkin
Scenario: a simple BEEP line parses to raw tokens
  Given the BEEP line "CAR\tk aa"
  When parse-line :beep-raw processes it
  Then the result is ["car" ("k aa")]

Scenario: a header/comment line is skipped
  Given the BEEP line "# BEEP UK dictionary header"
  When parse-line :beep-raw processes it
  Then the result is [nil nil]

Scenario: BEEP's symbol pseudo-words are excluded
  Given the BEEP line "!EXCLAMATION-POINT\teh k s k l ah m ey sh ah n p oy n t"
  When parse-line :beep-raw processes it
  Then the result is [nil nil]

Scenario: BEEP's RP-specific vowel tokens are kept raw, not translated here
  Given the BEEP line "CARE\tk ea"
  When parse-line :beep-raw processes it
  Then the result is ["care" ("k ea")], with "ea" untranslated —
    translation to "ɛə" is [US-021](US-021.md)'s job, not this story's

Scenario: load-dictionary-by-brand :beep-raw returns raw tokens for every word
  Given resources/data/beep_uk.dict is loaded via load-dictionary-by-brand :beep-raw
  When the result is inspected
  Then every value is a vector of raw space-joined MRPA token strings,
    none of which contain any IPA characters (e.g. no "ɛ", "ə", "ː")
```

## Data structure: `resources/data/beep_uk.dict`

Space/tab-separated, one pronunciation per line, uppercase headwords,
lowercase phonemes, `#`-prefixed header comment lines at the top. Same
word can repeat across consecutive lines for multiple pronunciations
(no `(2)`-style suffix, unlike CMUdict):

```
SHIP			sh ih p
SHIP'S			sh ih p s
!EXCLAMATION-POINT	eh k s k l ah m ey sh ah n p oy n t
```

Phoneme inventory (39 symbols, confirmed via `awk` over the full file):
`aa ae ah ao aw ax ay b ch d dh ea eh er ey f g hh ia ih iy jh k l m n ng
oh ow oy p r s sh sil t th ua uh uw v w y z zh`. No stress digits appear
anywhere in the corpus.
