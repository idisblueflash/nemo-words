# US-002. PoC on Google Books Ngram Views API - Done
As an engineer, I want to do a PoC on Google word frequency API so that I can understand the logic for US-003.

## Tech Notes
PoC is done and working: /Users/husongtao/Projects/nemo-words/scripts/word-freq.js.

node scripts/word-freq.js word1 word2 word3
node scripts/word-freq.js --file words.txt
cat words.txt | node scripts/word-freq.js

It hits Google Books Ngram Viewer's JSON endpoint (no official API/key exists for this), chunks words at 400/request (verified up to ~700 works in a single request), and prints word\<TAB\>freq (mean frequency over 2015–2019, configurable via --year-start/--year-end/--corpus). Tested with a 500-word batch across 3 chunks — all resolved correctly.

One thing worth flagging: I had to hand-roll HTTPS-over-CONNECT-proxy tunneling because your environment has HTTPS_PROXY=http://127.0.0.1:7897 set, which curl honors automatically but Node's https module ignores by default. That code is in httpsGetViaProxy() — it's a bit gnarly (manual TLS-over-tunnel with Content-Length-based completion detection, since the proxy doesn't propagate the server's Connection: close), but stays dependency-free per the repo's convention. If you're not behind that proxy on other machines, the script transparently falls back to a plain https.get.

## Acceptance Criteria

```gherkin
Scenario: Bulk lookup within a single chunk
  Given a batch of up to 400 words
  When the script queries the Ngram Viewer endpoint
  Then it makes exactly one request
  And prints one "word\tfreq" line per input word

Scenario: Bulk lookup spanning multiple chunks
  Given a batch of 500 words
  When the script queries the Ngram Viewer endpoint
  Then it splits the batch into 400-word chunks
  And every word across all chunks resolves to a printed "word\tfreq" line

Scenario: Behind the dev HTTPS_PROXY
  Given HTTPS_PROXY is set in the environment
  When the script makes a request
  Then it tunnels the TLS connection through the CONNECT proxy
  And the response is read to completion using Content-Length

Scenario: Not behind a proxy
  Given HTTPS_PROXY is not set
  When the script makes a request
  Then it falls back to a plain https.get call
```
