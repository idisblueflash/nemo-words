# US-014. Find the best-matched example word for a target word's syllable

As an engineer, I want to score a lexical set's candidate words by how closely their onset and coda match a target word's own syllable, so that the mnemonic-story feature gets the single best-sounding example instead of an arbitrary one.

## background
[[US-004]]'s `lexical-sets.edn` only holds a small, hand-picked, human-readable overview per set — not enough to find a *good* example for one specific target word, and not meant to be searched that way. Picking a good example needs the full dictionary pool, searched fresh every time and never persisted (this story never touches `lexical-sets.edn`).

The idea: given a target word (e.g. "gnarly", GA `/ˈnɑɹli/`) and the RP+GA pair of the lexical set it belongs to (e.g. RP `/ɑː/`, GA `/ɑɹ/`), pull every candidate word matching that pair, then score each candidate by how much of the target word's *own* syllable it echoes beyond the nucleus:
- +1 if the candidate's onset matches the target's onset (target's onset here is `n`, so a candidate like "narwhal" scores up)
- +1 if the candidate's coda matches the target's coda, when the target's syllable actually has one (two words both lacking a coda isn't a match worth scoring — it's the default, not a shared feature)

The best-scoring candidate(s) are the closest-sounding echo of the target word's syllable — the raw material for hooking the target word into a mnemonic sentence later. This is pure ranking/output; nothing gets saved.

## Protocol
`nemo-words.pairs/extract-syllable` — a pure function `[rp ga target-ga] -> {:onset :nucleus :coda} | nil`, sibling to [[US-013]]'s `extract-nucleus`: same syllable-segment selection (GA variant containing `target-ga`, RP variant with matching syllable count), but instead of trimming the onset/coda consonants away, it returns them alongside the nucleus. Reuses [[US-013]]'s consonant set and the deliberate exclusion of `ɹ` from it.

`nemo-words.match/score` — a pure function `[target-syllable candidate-syllable] -> int` (0, 1, or 2): `+1` when `:onset` strings are equal, `+1` when `:coda` strings are equal **and** `target-syllable`'s `:coda` is non-empty.

`nemo-words.match/best-candidates` — the composition: `[dict target-word rp ga] -> rows sorted by :score desc`.
```clojure
(defn best-candidates [dict target-word rp ga]
  (let [target (->> (ipa/lookup-rows dict {:word target-word})
                     first
                     (#(pairs/extract-syllable (:rp %) (:ga %) ga)))]
    (->> (ipa/lookup-rows dict {:rp rp :ga ga})
         (keep (fn [row]
                 (when-let [syll (pairs/extract-syllable (:rp row) (:ga row) ga)]
                   (assoc row :score (match/score target syll)))))
         (sort-by :score >))))
```
- [[US-001]] `ipa/lookup-rows` supplies both the target word's own row and the full candidate pool for the pair — the same full/unbounded search [[US-004]] deliberately stops doing, kept here because this is exactly where an unbounded pool belongs.
- Output only: `best-candidates` never reads or writes `lexical-sets.edn`. Whatever calls it (composing the mnemonic sentence) decides what to do with the ranked rows.

## Acceptance Criteria

```gherkin
Scenario: Onset match outranks nucleus-only match
  Given target word "gnarly" (GA "/ˈnɑɹli/") for pair rp "/ɑː/" ga "/ɑɹ/"
  And candidates "narwhal" (onset "n", same as target) and "starlet" (onset "st", different)
  When best-candidates is called
  Then "narwhal" is ranked above "starlet"

Scenario: Onset + coda match outranks onset-only match
  Given a target syllable with onset "n" and coda "r"
  And candidate A matches onset "n" and coda "r"
  And candidate B matches onset "n" but has a different coda
  When best-candidates is called
  Then candidate A is ranked above candidate B

Scenario: Coda scoring doesn't apply when the target has no coda
  Given a target syllable with onset "n" and an empty coda
  And candidate A matches onset "n" and also has an empty coda
  And candidate B matches onset "n" and has a non-empty coda
  When best-candidates is called
  Then candidate A's score reflects only the onset match, not a "coda match"
  And candidate A and candidate B are not distinguished by coda

Scenario: No candidates share the nucleus
  Given no row in the dict matches rp/ga for the given pair
  When best-candidates is called
  Then it returns an empty seq
  And no error is raised

Scenario: Nothing is persisted
  Given lexical-sets.edn exists with some entries
  When best-candidates is called with any target word and pair
  Then lexical-sets.edn is byte-for-byte unchanged afterward
```
