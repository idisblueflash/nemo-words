# US-010. Generic top-N ranking function
As an engineer, I want a reusable "rank by score, keep top N" function, so [[US-004]] and [[US-008]] don't each reimplement the same truncation logic.

## background
Both building an existing set and extending to a new one end with the same step: sort rows by a score key and keep the top N. Factoring it into one function means one implementation, one set of unit tests, and both pipelines just call it.

## Protocol
`nemo-words.rank/top-n` — `[rows score-key n] -> rows`, `(->> rows (sort-by score-key >) (take n))`. Pure, no CLI; called in-process by [[US-004]]'s `build-set` and [[US-006]]'s `extend-set`. Unit-tested directly on plain maps/vectors.

## Acceptance Criteria

```gherkin
Scenario: More rows than N
  Given 100 rows with distinct :freq values
  When top-n is called with score-key :freq and n 60
  Then exactly 60 rows are returned
  And every returned row's :freq is >= every non-returned row's :freq

Scenario: Fewer rows than N
  Given 12 rows
  When top-n is called with n 60
  Then all 12 rows are returned, unchanged
  And no error is raised

Scenario: Tied scores
  Given several rows share the same score at the N/N+1 boundary
  When top-n is called
  Then ties are broken by input order (stable sort)

Scenario: Empty input
  Given an empty seq of rows
  When top-n is called
  Then it returns an empty seq
```
