# US-016. A better kaikki IPA dictionary extractor

As an engineer, I want a replacement for `scripts/build-kaikki-ipa-dict.js`
that recovers a word's untagged pronunciation data instead of dropping the
word outright, so `en_US_RP_ipa.tsv` covers common words it currently
misses and downstream tools like [[US-015]]'s `populate-lexical-sets`
have real seed data to verify against.

## background
See [[issue-001-kaikki-dict-missing-common-words]] for the full
investigation (root cause, scope, and rejected alternatives) — not
repeated here.

## Investigation findings (2026-08-23)

Full findings moved to
[[investigation-002-us-016-kaikki-dialect-tag-gating]]. Summary: verified
the proposed dialect-tag-gating fix against the full local
`resources/data/kaikki-en.jsonl` (1,487,639 lines). AC1-AC3 all hold
against real data; the fix recovers 19,734 words (33.8% of the old drop
set), including `myth` and `cancel`, which issue-001 had assumed needed
Option-3 supplementation but turn out fixed by this fix alone. One edge
case the original ACs didn't cover — a genuinely different third-region
real-ipa entry (e.g. Ireland-tagged) still blocking the untagged
fallback — led to a decision (reflected below) to treat British-Isles
tags (`Ireland`, `Northern-Ireland`, the newer `["British","Southern",
"Standard"]` combo) as RP candidates rather than blocking regions; the
Protocol and gherkin scenarios below already incorporate that decision.
Also flagged, and folded in here: a separate coverage gap where 224 words'
RP-equivalent data hides under the newer 3-tag convention with no
`RP`/`Received-Pronunciation` tag present.

## Protocol
Mostly the same output contract as the script it replaces, plus one new
column: reads `resources/data/kaikki-en.jsonl` (local file, or streams
`SOURCE_URL` if absent), writes
`word<TAB>GenAm-IPA<TAB>RP-IPA<TAB>Homophone` rows to
`resources/data/en_US_RP_ipa.tsv` (or the given output path), same CLI
usage (`node <script> [output-path] [input-jsonl-path]`). The dialect-tag
gating logic is rewritten so a `sounds` entry only counts toward
`hasAnyRegionalTag` or a per-dialect candidate when it actually carries
an `ipa` value — a region-tagged entry with no `ipa` (audio-only) is
treated as absent, not as blocking the untagged fallback.

The RP tag set is widened to cover British-Isles English varieties, not
just the literal `RP`/`Received-Pronunciation` tags:
- the newer Wiktionary tag combo `["British", "Southern", "Standard"]`
  (2,823 real-ipa entries in the corpus use this instead of the older
  tag) counts as an RP candidate;
- other British-Isles regional tags such as `Ireland` (and similarly
  `Northern-Ireland`) count as RP candidates too, rather than as an
  unrelated "other region" that blocks the untagged fallback. A
  real-ipa entry tagged this way is treated exactly like a
  `Received-Pronunciation`-tagged one: it wins the RP-IPA slot over the
  untagged fallback (per the dialect-tagged-wins rule), and unlike a
  genuinely unrelated region (e.g. Canada, Southern-US), it does not by
  itself block the GenAm-IPA column's untagged fallback.

The `Homophone` column is populated from the first `sounds` entry
(untagged or tagged, in array order) that carries a `homophone` field,
regardless of whether the entry also has an `ipa` value — a
`homophone`-only entry (no `ipa`) is not otherwise usable and should
still surface here. Empty if no `sounds` entry has a `homophone` field.
A word isn't dropped just because it lacks a homophone — that only
depends on GenAm-IPA/RP-IPA per the scenarios above.

## Data structure: `resources/data/kaikki-en.jsonl`

One JSON object per line. Top-level keys relevant here:

```
word, lang, lang_code, pos, senses, forms, sounds, ...
```

`sounds` is an array of objects, each describing one pronunciation variant.
Observed keys across a 30k-line sample (not every object has every key):

```
tags, ipa, enpr, note, audio, ogg_url, mp3_url, homophone, rhymes, topics, text, other
```

Shapes that matter for the extractor:

- **Untagged, real ipa** (no `tags` key at all): e.g.
  `{"ipa": "/θɪˈsɔːɹəs/"}` for "thesaurus". This is the fallback value
  AC1 wants recovered.
- **Region-tagged, real ipa**: e.g.
  `{"tags": ["Received-Pronunciation"], "ipa": "/ˈdɪk.ʃə.nə.ɹi/"}`,
  `{"tags": ["US"], "ipa": "/ˈdɪk.ʃəˌnɛ.ɹi/"}`.
- **Region-tagged, audio-only (no `ipa` key)**: e.g.
  `{"audio": "En-us-dictionary.ogg", "tags": ["California"], "ogg_url": "...", "mp3_url": "..."}`.
  This is the case the current script wrongly treats as "region covered,
  so don't fall back to untagged" — it has no `ipa` at all.
- **`tags` can hold multiple region labels in one array**, e.g.
  `{"tags": ["British", "Southern", "Standard"], "ipa": "/fɹɪj/"}` — a
  single sounds entry isn't always one-region-per-entry.
- **`enpr`-only entries** (no ipa, e.g. `{"tags": ["US"], "enpr": "dĭk'shə-nĕr-ē"}`)
  carry no IPA and should be treated the same as audio-only: present but
  not usable as an `ipa` value.
- No empty-string `ipa` values (`""`) observed in the sample — when `ipa`
  is present it's always non-empty; absence is signaled by the key being
  missing entirely, not by an empty string.
- `note`-only untagged variants exist too (dialectal notes without a
  `tags` array), e.g. `{"note": "Humberside, Teesside, fair–fur merger", "ipa": "/wɛːd/"}`
  for "word" — still untagged by the `tags` key, so still eligible as the
  untagged fallback.
- `homophone`-only entries (no `ipa`) also occur and should be ignored
  the same way as audio-only ones, e.g. `{"homophone": "pi"}` for "pie",
  `{"homophone": "pawned (cot–caught merger)"}` for "pond", or
  `{"homophone": "buck (without the foot-strut split, when pronounced /bʊk/)"}`
  for "book" — some are plain homophones, others merger-conditional, but
  none carry an `ipa` key either way.
