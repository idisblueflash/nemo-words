# US-019. Build `ga_rp.tsv` and rename the raw-token loader

Part of [FEAT-002](FEAT-002.md) (split for parallel implementation — see that
feature for the full background). **Depends on [US-017](US-017.md) and
[US-018](US-018.md) both landing first** — this story unions their two brands.

As an engineer, I want a build step that writes
`resources/data/ga_rp.tsv` from CMUdict (GA) + BEEP (RP) raw phoneme
tokens, and a renamed loader that reads it back unchanged (no IPA
translation), so the dictionary all of
[US-001](US-001.md)/[US-004](US-004.md)/[US-005](US-005.md)/[US-006](US-006.md)/[US-014](US-014.md) read from matches
[ADR-0002](../decisions/0002-switch-cmudict-beep-primary-dictionary.md)'s measured winner (92.9% composite agreement against the
Lexical Sets Table, 100% coverage) instead of Kaikki's post-US-016 58.7%,
and matches [0003-match-nucleus-against-arpabet-mrpa-tokens](../decisions/0003-match-nucleus-against-arpabet-mrpa-tokens.md)'s decision
to keep raw tokens as the single on-disk source of truth.

## background
[US-017](US-017.md) adds `:cmudict-raw` (raw ARPABET tokens from CMUdict).
[US-018](US-018.md) adds `:beep-raw` (raw MRPA tokens from BEEP). This story is
where those two come together: union them into one TSV, then rebuild the
read side (`load-rp-ga-dict` and friends) around the new raw-token
format instead of the old pre-translated-IPA one.

IPA display conversion (`ga-tokens->ipa`/`rp-tokens->ipa` and their
reverse direction) is **not** this story's job — it's split out into
[US-020](US-020.md) (ARPABET↔IPA) and [US-021](US-021.md) (MRPA↔IPA), both pure conversion
functions with no dependency on this story's file format beyond the
shared convention (comma-joined variants of space-joined tokens) all
four raw-token stories already agree on.

## Protocol

### Build step
A new CLI subcommand (matching the `ipa-lookup`/`build-set`/
`populate-lexical-sets` pattern in `core.clj`) that:
1. Loads `:cmudict-raw` and `:beep-raw` via `load-dictionary-by-brand`.
2. For the union of both brands' words, builds one row per word:
   `{:word w :ga (comma-join cmudict-raw-variants) :rp (comma-join
   beep-raw-variants)}` — comma-joining multiple raw-token variants the
   same way the old IPA file's multi-variant cells did (US-001
   background), `""` (not omitted) when a word is present in only one
   brand.
3. Drops a word entirely only if **both** GA and RP are empty (mirrors
   US-016's drop rule; a word found in just one source still gets a row).
4. Writes `word<TAB>GA-tokens<TAB>RP-tokens` rows to
   **`resources/data/ga_rp.tsv`** — the only on-disk pronunciation file
   per ADR-0003; no `ga_rp_ipa.tsv`/`en_US_RP_ipa.tsv` is written or
   kept. The old Kaikki-built `resources/data/en_US_RP_ipa.tsv` is
   deleted once the new file is confirmed working.

### Read path
- `nemo-words.ipa/load-rp-ga-dict` is renamed `load-ga-rp-dict` and
  re-pointed at `resources/data/ga_rp.tsv`. It keeps returning raw token
  strings unchanged (no IPA translation at load) as
  `{:word :ga-tokens :rp-tokens}` rows — a thin, format-preserving
  loader, same shape discipline as before (`""` not nil for an absent
  cell, comma-joined variants kept as-is).

### Nucleus matching (ADR-0003)
Any lexical-set/nucleus matching logic (e.g. `populate-lexical-sets`)
should compare directly against the raw `:ga-tokens`/`:rp-tokens` fields
— single discrete phoneme tokens, no ligature decomposition needed — not
against IPA-encoded output. Existing consumers (`lookup-rows`,
`word-matches?`, and the US-004/005/006/014 stories built on them)
currently query by IPA substring against the old `:rp`/`:ga` keys;
migrating those call sites to token-based matching is a wider change
across several stories and is **out of scope here** — see Follow-up.

`scripts/build-kaikki-ipa-dict.js` is retired (left in place for
historical/Kaikki-revival reference per ADR-0002's "not a blocker"
framing, but no longer part of the regeneration path) once this ships.

## Acceptance Criteria

```gherkin
Scenario: a word present in both CMUdict and BEEP gets both columns populated with raw tokens
  Given "car" exists in CMUdict as "K AA1 R" and in BEEP as "k aa"
  When the dictionary is built
  Then the output row for "car" has a non-empty GA column containing raw ARPABET tokens "K AA1 R"
  And a non-empty RP column containing raw MRPA tokens "k aa"

Scenario: the build step does not translate to IPA
  Given "car" exists in CMUdict as "K AA1 R"
  When the dictionary is built
  Then the GA column for "car" in resources/data/ga_rp.tsv is "K AA1 R", not "/kˈɑɹ/"

Scenario: a word found in only one source still gets a row with one empty column
  Given a word exists in CMUdict but not in BEEP
  When the dictionary is built
  Then the output row has a non-empty GA column and an empty RP column
  And the word is not dropped from the output

Scenario: a word found in neither source is absent
  Given a word exists in neither CMUdict nor BEEP
  When the dictionary is built
  Then no row for that word appears in the output

Scenario: BEEP's symbol pseudo-words are excluded
  Given BEEP contains an entry for the pseudo-word "!EXCLAMATION-POINT"
  When the dictionary is built
  Then no row for "!EXCLAMATION-POINT" (or any other non-alphabetic
    pseudo-word) appears in the output

Scenario: multiple pronunciation variants are comma-joined, same convention as before
  Given "read" has two CMUdict entries, "READ R IY1 D" and "READ(2) R EH1 D"
  When the dictionary is built
  Then the GA column for "read" contains both raw-token variants comma-separated,
    "R IY1 D,R EH1 D"

Scenario: load-ga-rp-dict reads the renamed file into raw-token rows
  Given resources/data/ga_rp.tsv has been built by this build step
  When nemo-words.ipa/load-ga-rp-dict reads it
  Then it returns {:word :ga-tokens :rp-tokens} rows with raw token strings unchanged,
    "" (not nil) for an absent cell
```
