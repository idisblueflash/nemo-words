# US-006. Extend the Lexical Sets
As an engineer, I want to build new sets so that I can support more cases for the user.

## background
Some IPA combinations don't exist in `lexical-sets.edn` yet. Same functions as [[US-004]], plus two extra in-process steps to find the pair and the keyword:

```clojure
(defn extend-set [dict lexical-sets ga]
  (let [[rp ga*] (pairs/dominant-pair (ipa/lookup-rows dict {:ga ga}) ga)
        ranked   (->> (ipa/lookup-rows dict {:pair-substring [rp ga*]})
                       (freq/annotate-freq)
                       (rank/top-n :freq 60))
        kw       (keyword/pick-keyword ranked)]
    (sets/save! (sets/upsert lexical-sets kw ranked))))
```

- [[US-007]] `pairs/dominant-pair` — pick the winning RP+GA nucleus pair (a bare fragment like `["ɑː" "ɑɹ"]`, not a full cell — see its "Nucleus extraction" section). [[US-001]]'s `{:pair-substring [rp ga]}` opt is what re-gathers the full word list from that fragment.
- [[US-008]] — superseded: ranking reuses [[US-010]] `rank/top-n`, same as [[US-004]].
- [[US-009]] `keyword/pick-keyword` — choose the representative headword.
- [[US-011]] `sets/upsert` + `sets/save!` — persist the new set.

This story is `extend-set` itself — composition/glue only. [[US-007]] and [[US-009]] are the only new logic, and both are pure/isolated functions, buildable and unit-testable independently of the rest of the pipeline (no shell process involved).

## Acceptance Criteria

```gherkin
Scenario: Extend with a genuinely missing GA combination
  Given lexical-sets.edn has no set defined by GA "/ɑɹ/"
  And the dictionary has triples matching GA "/ɑɹ/" with a clear dominant RP pairing (e.g. "car", "far", "star", "gnarly" dominantly pairing to nucleus ["ɑː" "ɑɹ"], per [[US-007]]'s "One RP nucleus clearly dominates" scenario)
  When extend-set is called with ga "/ɑɹ/"
  Then the dominant RP+GA pair is used to gather and rank matching words (["ɑː" "ɑɹ"] is passed as `{:pair-substring [rp ga]}` to re-gather every row whose raw cells contain that nucleus, e.g. "car", "far", "star", "gnarly", "narwhal")
  And a new keyword is chosen from those top 60 (the keyword is one of the 60 saved words, not an extra 61st — matching the `build-set` code sample above, which calls `top-n :freq 60` before `pick-keyword`; per Wells' convention a word like "car" is a plausible pick for this /ɑɹ/-nucleus set)
  And lexical-sets.edn gains a new entry under that keyword

Scenario: GA combination already covered
  Given lexical-sets.edn already has a set whose GA is "/ɑɹ/" (e.g. an existing entry keyed by keyword "car")
  When extend-set is called with the same ga
  Then the existing entry is upserted (replaced), not duplicated

Scenario: No matches for the given GA at all
  Given the dictionary has zero triples matching the queried GA (e.g. ga "/ɒː/", a combination absent from the GA inventory entirely)
  When extend-set is called
  Then it reports that no dominant pair could be found
  And lexical-sets.edn is left unchanged
```
