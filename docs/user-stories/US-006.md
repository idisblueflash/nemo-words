# US-006. Extend the Lexical Sets
As an engineer, I want to build new sets so that I can support more cases for the user.

## background
Some IPA combinations don't exist in `lexical-sets.edn` yet. Same functions as [[US-004]], plus two extra in-process steps to find the pair and the keyword:

```clojure
(defn extend-set [dict lexical-sets ga]
  (let [[rp ga*] (pairs/dominant-pair (ipa/lookup-rows dict {:ga ga}))
        ranked   (->> (ipa/lookup-rows dict {:pair [rp ga*]})
                       (freq/annotate-freq)
                       (rank/top-n :freq 60))
        kw       (keyword/pick-keyword ranked)]
    (sets/save! (sets/upsert lexical-sets kw ranked))))
```

- [[US-007]] `pairs/dominant-pair` — pick the winning RP+GA pair.
- [[US-008]] — superseded: ranking reuses [[US-010]] `rank/top-n`, same as [[US-004]].
- [[US-009]] `keyword/pick-keyword` — choose the representative headword.
- [[US-011]] `sets/upsert` + `sets/save!` — persist the new set.

This story is `extend-set` itself — composition/glue only. [[US-007]] and [[US-009]] are the only new logic, and both are pure/isolated functions, buildable and unit-testable independently of the rest of the pipeline (no shell process involved).

## Acceptance Criteria

```gherkin
Scenario: Extend with a genuinely missing GA combination
  Given lexical-sets.edn has no set defined by GA "/ɑːr/"
  And the dictionary has triples matching GA "/ɑːr/" with a clear dominant RP pairing
  When extend-set is called with ga "/ɑːr/"
  Then the dominant RP+GA pair is used to gather and rank matching words
  And a new keyword is chosen from those top 60 (the keyword is one of the 60 saved words, not an extra 61st — matching the `build-set` code sample above, which calls `top-n :freq 60` before `pick-keyword`)
  And lexical-sets.edn gains a new entry under that keyword

Scenario: GA combination already covered
  Given lexical-sets.edn already has a set whose GA is "/ɑːr/"
  When extend-set is called with the same ga
  Then the existing entry is upserted (replaced), not duplicated

Scenario: No matches for the given GA at all
  Given the dictionary has zero triples matching the queried GA
  When extend-set is called
  Then it reports that no dominant pair could be found
  And lexical-sets.edn is left unchanged
```
