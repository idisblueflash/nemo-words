A stratified reading of the codebase

Three files, four layers. Bedrock at the bottom is the standard library; everything above it is built to depend only on what's beneath. This is a manual cross-section — cut through the actual :require forms — kept separate from the auto-generated docs/nemo_words.dgml call graph.

Cross-section

Entry points sit at the surface, the standard library is bedrock. Arrows run downhill, in the direction of dependency. The dashed line is the one place a domain namespace reaches past its adapter, straight to bedrock.

The four strata

Read bottom to top: each layer is built on the one beneath it, and knows nothing about the one above.

Entry points

nemo-words.ipa/-main parses word arguments, calls the L2 loaders, and prints. nemo-words.core/-main is the project scaffold's own "Hello" entry point — orchestration only, no business logic in either.

L2domain

nemo-words.ipa

ARPABET→IPA conversion (arpabet->ipa, arpabet-phoneme->ipa, arpabet-vowels), the three cross-referenced source loaders (load-ipa-dict, load-wikipron, load-cmudict), and output formatting (fmt).

Depends on L1 for every string operation, and reaches directly into L0's clojure.java.io for resource IO — the one place bedrock is touched outside the adapter layer.

L1adapter

nemo-words.strutil

Renames clojure.string's call sites to a verb-str form — replace-str, trim-str, split-str, lower-case-str, blank-str?, join-str. Its only purpose is the naming seam: domain code depends on this namespace, never on the external lib directly.

L0external
/ stdlib

clojure.string · clojure.java.io

Not part of this project. Consumed only by L1, or directly by L2 where no adapter exists yet.

Dependency rule

No upward or sideways edges: L1 never calls into L2 or L3, and L2 never calls core.clj or vice versa.

strutil (L1)->clojure.string (L0)
ipa (L2)->strutil (L1), clojure.java.io (L0)
ipa/-main (L3)->ipa (L2)
core/-main (L3)->nothing yet

The ipa (L2) -> clojure.java.io (L0) edge is the exception drawn as a dashed fault line above — it skips the adapter layer because no L1 IO wrapper exists yet.

Next core samples

  • ipa.clj's resource-reader calls clojure.java.io straight from L2 — there's no L1 IO adapter (an nemo-words.iolib, say) mirroring what strutil does for clojure.string.
  • core.clj is an unconnected scaffold: it doesn't call into the ipa domain, so it's a dangling L3 node with nothing beneath it.
