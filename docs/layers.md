# Stratified design — `src/nemo_words/`

Hand-authored (not generated by `scripts/gen-dgml.sh`). Layers are ordered
bottom-up; each layer may depend only on layers below it.

```
 L3  entry points     nemo-words.ipa/-main      nemo-words.core/-main
                              |                          |
 L2  domain           nemo-words.ipa
                       (arpabet->ipa, load-ipa-dict, load-wikipron,
                        load-cmudict, fmt)
                              |                \
 L1  adapter          nemo-words.strutil        \
                       (replace-str, trim-str,    \
                        split-str, lower-case-str, \
                        blank-str?, join-str)       \
                              |                      \
 L0  external/stdlib  clojure.string          clojure.java.io
```

## Layers

**L0 — external / stdlib**
`clojure.string`, `clojure.java.io`, `clojure.core`. Not part of this
project; only ever consumed by L1, or directly by L2 where no adapter
exists yet (see Gaps).

**L1 — adapter (`nemo-words.strutil`)**
Renames `clojure.string`'s call sites to a verb-`str` form (`replace-str`,
`trim-str`, `split-str`, `lower-case-str`, `blank-str?`, `join-str`). Sole
purpose is a naming seam: domain code depends on this namespace instead of
reaching into the external lib directly. Depends only on L0.

**L2 — domain (`nemo-words.ipa`)**
ARPABET→IPA conversion (`arpabet->ipa`, `arpabet-phoneme->ipa`,
`arpabet-vowels`), the three cross-referenced source loaders
(`load-ipa-dict`, `load-wikipron`, `load-cmudict`), and output formatting
(`fmt`). Depends on L1 (`strutil`) for all string manipulation, and on L0
(`clojure.java.io`) directly for resource IO — the one place L0 is touched
outside L1, since no IO adapter layer exists yet.

**L3 — entry points**
`nemo-words.ipa/-main` (parses word args, calls the L2 loaders, prints) and
`nemo-words.core/-main` (project scaffold, currently a standalone "Hello"
entry point not wired into the `ipa` domain). Orchestration only, no
business logic.

## Dependency rule

```
strutil (L1)      -> clojure.string (L0)
ipa (L2)          -> strutil (L1), clojure.java.io (L0)
ipa/-main (L3)    -> ipa (L2)
core/-main (L3)   -> (nothing yet)
```

No upward or sideways edges: L1 never calls into L2/L3, and L2 never calls
core.clj or vice versa.

## Gaps / next stratification candidates

- `ipa.clj`'s `resource-reader` calls `clojure.java.io` straight from L2 —
  there's no L1 IO adapter (e.g. an `nemo-words.iolib`) mirroring
  `strutil`'s treatment of `clojure.string`.
- `core.clj` is an unconnected scaffold; it doesn't yet call into the `ipa`
  domain, so it's a dangling L3 node.
